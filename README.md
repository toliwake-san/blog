# つきなみ文庫

Markdownで書いて、コマンド1つでサイトになります。外部ライブラリは不要（Python 3 だけ）。

## 考え方

**投稿タイプがありません。** 記事も、本も、人も、タグも、すべて `pages/` に置かれた同じ形式のページです。
「これは本、これは日記」という分類をシステム側に持たせない。かわりに、**リンクによって構造が浮かび上がる**ようにしてあります。

リンクは2種類あります。

| 種類 | 書き方 | 意味 |
|---|---|---|
| **tag link** | frontmatter の `tags:` | A **は** B である（所属・分類） |
| **body link** | 本文中の `[[ ]]` | A **が** B に言及する（参照） |

そして `layout` で、そのページに集まってきたリンクの見せ方を決めます。

| layout | 何が並ぶか | 使いどころ |
|---|---|---|
| `page` | 本文＋言及の引用 | 日記、本そのもののページ |
| `grid` | タグづけされたページがカードで並ぶ | 「本」「人」などの一覧 |
| `table` | 同じものが表で並ぶ | 件数が多い一覧 |
| `list` | 同じものが箇条書きで並ぶ | 軽い一覧 |

つまり「本の一覧ページ」を作る機能はありません。`本` というページを作って `layout: grid` にし、各本のページに `tags: 本` と書く。それだけで一覧になります。同じやり方で「人」「映画」「行った場所」も増やせます。

## まいにちの手順

```bash
cd ~/Desktop/blog

python3 new.py "今日のタイトル"    # ひな型ができてエディタが開く → 書く
python3 build.py --serve           # http://localhost:8000 で確認
./publish.sh                       # 公開
```

タグをつけて作ることもできます。

```bash
python3 new.py "銀河鉄道の夜" 本        # 本を1冊登録する
python3 new.py "宮沢賢治" 人 --grid     # 「人」の一覧に載る、それ自体も一覧ページ
python3 new.py "考えかけ" --note        # 検索避け（noindex）のメモ
python3 new.py "内緒" --unlisted        # 一覧にもバックリンクにも出さない
```

ページ名がファイル名になります。既存の名前を指定すると、そのファイルが開きます。

## 本と日記をつなぐ

1. `python3 new.py "銀河鉄道の夜" 本` で本のページを作る
2. 日記の本文で `[[銀河鉄道の夜]]` と書く
3. ビルドすると、**その段落がまるごと本のページに引用として集まる**

引用の下のリンクから元の記事に飛べます。本のページを開けば、その本についていつ何を書いてきたかが時系列で並びます。

**本の話は一段落にまとめて書く**のがコツです。段落の単位で切り出されます。

表示する文字を変えたいときは `[[銀河鉄道の夜|あの本]]` のように縦棒で区切ります。

同じ `[[ ]]` にページ名を書けば、日記どうしもつながります。リンクされた側にはバックリンクが自動でたまります。

**参照先のページは、なければ自動で作られます。** 本を読んだその場で `[[カフカ『城』]]` と書けば、その本のページができて、以後そこに言及が集まっていきます。先にページを用意する必要はありません。

自動で作られたページの設定はこうなります。

| | tag（`tags:` から） | body link（`[[ ]]` から） |
|---|---|---|
| layout | `grid`（一覧ページ） | `page` |
| 判型 | — | 文庫 |
| face | — | false |
| トップの棚 | 出ない | 出る |

**ビルドすると `pages/` に .md ファイルも作られます。** 中身は空で、frontmatter だけが入っています。あとから本文を書き足したり、判型を変えたりできます。書くまでは、言及の引用だけが並ぶ空の一冊として棚に並びます。

すでにあるファイルは上書きしません。ビルドのたびに、新しく作られたファイルが一覧で表示されます。

```
+ 参照されていたページを 2 件つくりました:
   pages/カフカ『城』.md
   pages/読書.md
```

ファイルを作らせたくない場合は `build.py` の `AUTO_CREATE_FILES` を `False` にしてください。サイト上にだけページができます。

## 画像を入れる

1. 画像ファイルを `static/images/` に入れる（Finderでドラッグでも可）
2. 本文にこう書く

```markdown
![夕暮れの神社](images/jinja.jpg)
```

角カッコの中がキャプションになり、写真の下に小さく出ます。空にすればキャプションなしです。

大きく出したいときは末尾に `"wide"` をつけます。本文の幅を超えて、中央に大きく表示されます。

```markdown
![夕暮れの神社](images/jinja.jpg "wide")
```

一覧のカードに大きく出したいときは、frontmatter の `cover:` に指定します。

```
cover: images/jinja.jpg
```

パスは常に `images/...` から書きます（`../` は不要です。フォルダの深さは自動で調整されます）。

写真は撮ったままだと数MBあることが多いので、長辺1600px程度に縮めておくと表示が軽くなります。

## URLを埋め込む

**URLだけを1行に置く**と、埋め込み表示になります。前後は空行にしてください。

```markdown
今日みた映像。

https://www.youtube.com/watch?v=xxxxxxxx

よかった。
```

対応しているサービス:

| サービス | 備考 |
|---|---|
| YouTube | `watch?v=` / `youtu.be` / `shorts` / `live`。`&t=42` の秒数指定も効きます |
| Vimeo | |
| Spotify | 曲・アルバム・プレイリスト・ポッドキャスト |
| SoundCloud | |
| Google マップ | 「地図を埋め込む」で出るURL |

それ以外のURLは、リンクカード（枠付きのリンク）になります。X（旧Twitter）やInstagramの埋め込みは、先方のトラッキング用スクリプトを読み込む必要があるため対応していません。リンクカードとして表示されます。

YouTubeは `youtube-nocookie.com` 経由で埋め込んでいるので、再生するまでCookieは置かれません。

文中に普通のリンクを置きたいときは、これまで通り `[表示する文字](URL)` と書いてください。行に単独で置いたときだけ埋め込みになります。

## 本棚ビュー

トップは**本棚**と**ブロック**の2通りで見られます。右上のアイコンで切り替わり、選んだ表示はブラウザに記憶されます（既定は本棚）。

- **厚み** — 本文の文字数の対数で決まります。30字で23px、400字で41px、1500字で57px、それ以上は72pxで頭打ち。長文でも際限なく太らないようにしてあります
- **高さ** — frontmatter の `size:` で選びます
- **段** — 画面幅に入るだけ並び、入りきらない分は次の段に落ちます。段ごとに棚板が引かれます

### 判型

```
size: 新書
```

| 指定 | 高さ |
|---|---|
| `文庫`（既定） | 250px |
| `新書` | 292px |
| `単行本` | 330px |
| `ハードカバー` | 372px |
| `大型本` | 430px |

高さは `build.py` の `BOOK_SIZES`、厚みの範囲は `SPINE_MIN` / `SPINE_MAX` で変えられます。

判型は「その文章をどう置きたいか」で選んでください。長さとは無関係にできます。短くても大事な一篇を大型本にする、といった使い方ができます。

### 面陳（表紙を見せる）

```
face: true
```

背表紙ではなく表紙を正面に向けて置きます。表紙の画像は `cover:` があればそれを、なければ**本文中の最初の画像**を自動で使います。どちらもなければ無地の表紙になります。

毎回やると本棚に見えなくなるので、月に1〜2冊にとどめるときれいです。

### 背表紙が入りきらないとき

長いタイトルは薄い背に収まりません。背表紙用の短い名前を指定できます。

```
title: インテリアコーディネートの基本について考えたこと
spine: インテリアの基本
```

入りきらなそうなページは、ビルド時に一覧で知らせます。

## ページの設定項目

```
---
title: 銀河鉄道の夜
date: 2026-08-11
tags: 本, 宮沢賢治
layout: page
visibility: public
permanent: true
cover: images/ginga.jpg
nav: 2
home: false
---
```

| 項目 | 説明 |
|---|---|
| `title` | ページ名。`[[ ]]` で参照するときの名前。省略時はファイル名 |
| `date` | `YYYY-MM-DD`。なくてもよい（本や人のページには不要） |
| `tags` | tag link。**書いた先のページが自動で作られます** |
| `layout` | `page` / `grid` / `table` / `list`。省略時 `page` |
| `visibility` | `public` / `unlisted` / `private` |
| `permanent` | `false` にすると note ページ（`noindex, nofollow`） |
| `cover` | 一覧カードに出す画像。`static/images/` に置いて `images/名前.jpg` |
| `size` | 本棚での判型。`文庫` / `新書` / `単行本` / `ハードカバー` / `大型本` |
| `face` | `true` で面陳（表紙を正面に向ける） |
| `spine` | 背表紙用の短いタイトル |
| `home` | `false` にするとトップの一覧に出ない |

### visibility

- `public` — 誰でも見える。一覧にも出る
- `unlisted` — URLを直接開けば見えるが、一覧にもバックリンクにも出ない。文脈を辿らないと着かない状態
- `private` — ビルドされない。手元にだけ残る

`protected`（パスワード付き）は静的サイトの範囲外なので未対応です。

### permanent

`true` が既定です。`false` にすると note ページ扱いになり、検索エンジンにインデックスされません（`noindex, nofollow`）。書きかけの考えを気楽に置いておくためのものです。ページには小さく `note` と表示されます。

## フォルダの中身

```
blog/
├── pages/        ← すべてのページ。ここだけ触る
├── static/
│   ├── style.css ← デザイン
│   └── images/   ← 写真・書影
├── build.py      ← ビルド（設定はこの先頭）
├── new.py        ← ページをつくる
├── publish.sh    ← ビルドして公開
└── docs/         ← 自動生成。編集しない
```

`pages/` の中はフォルダで整理してもかまいません。フォルダはURLに反映されるだけで、分類としての意味は持ちません。

## Obsidian で書く

`pages/` フォルダを Obsidian の vault として開けば、そのまま使えます。frontmatter も `[[ ]]` も互換です。Obsidian 側のグラフビューやバックリンクも動きます。

書くのは Obsidian、公開は `./publish.sh` ── という分担が一番ラクです。

## 続けるための運用ルール

**基準を下げる。** 3行でも1ページとする。トップはブロック並びなので、短いものは小さいタイルになって自然に馴染みます。

**書く時間を固定する。** ネタができたら書く方式は必ず止まります。

**本や人の話は一段落にまとめる。** そうしておくと、あとでそのページを開いたときに読めるものが残ります。日々の記事は流れていきますが、集約先のページには積み上がっていく。この非対称がこのサイトの資産です。

**分類に迷ったらタグを増やす。** ページは勝手に作られるので、コストはゼロです。あとから見て意味がなければ消せばいい。

**書けない日は既存ページに一行足す。** 新規である必要はありません。

**アクセス数を見ない。** 解析を入れていないのは意図的です。

**月に1回「つながり」を眺める。** 図がどう育ったかを見るのが、続けることのごほうびになります。

## 設定を変える

`build.py` の冒頭:

```python
SITE_TITLE = "つきなみ文庫"
SITE_DESCRIPTION = "読んだ本と、日々のこと。"
AUTHOR = "asage"
BASE_URL = "https://toliwake-san.github.io/blog"
```

デザインは `static/style.css` の先頭の変数で:

```css
--ink: #1a1a1a;    /* 文字色 */
--paper: #ffffff;  /* 背景色 */
--measure: 34rem;  /* 記事の1行の長さ */
--wide: 1180px;    /* 一覧の横幅 */
```

一覧の列数は `.grid { column-count: 4 }`。本文を明朝からゴシックにするなら `.post-body` の `var(--serif)` を `var(--sans)` に。

## 困ったとき

| 症状 | 対処 |
|---|---|
| ページが出てこない | `visibility: private` になっていないか |
| 一覧に出ない | `visibility: unlisted` か `home: false` になっていないか |
| `[[ ]]` が点線になる | ページ名が正確か確認。タグと違い、body link はページを自動生成しません |
| 一覧ページに何も並ばない | 並べたいページ側に `tags:` でその名前を書く（逆ではない） |
| 順番がおかしい | `date:` が `YYYY-MM-DD` か確認。日付なしは下に沈みます |
| デザインが崩れた | `docs/` を消して `python3 build.py` |
