# つきなみ文庫 — 運用ガイド

Markdownで書いて、コマンド1つでサイトになります。外部ライブラリは不要（Python 3 だけ）。

サイトの構造は3つ。

- **記事** — ブロック（タイル）状に並ぶ一覧
- **本** — 記事のなかで触れた本を、本ごとに集約したページ
- **つながり** — 記事と本の参照関係の図

---

## 1. まいにちの手順

```bash
cd ~/Desktop/blog

python3 new.py "今日のタイトル"    # ひな型ができてエディタが開く → 書く
python3 build.py --serve           # http://localhost:8000 で確認
./publish.sh                       # 公開
```

本を新しく登録するとき:

```bash
python3 new.py -b "銀河鉄道の夜"
```

## 2. 本と記事をつなぐ仕組み

ここがこのサイトの中心です。

### 手順

1. `python3 new.py -b "書名"` で本を登録する（`books/` にファイルができる）
2. 記事の本文で `[[書名]]` と書く
3. ビルドすると、**その段落がまるごと本のページに引用として集まる**

つまり本のページを見れば、「この本について、いつ、どんなふうに書いてきたか」が時系列で並びます。引用の下のリンクから元の記事に飛べます。

### 書き方の例

```markdown
こういうとき、いつも[[銀河鉄道の夜]]の丘の場面を思い出す。
あの本を読んで以来、夕方の高いところに登ると落ち着かない。
```

この段落が、そのまま「銀河鉄道の夜」のページに載ります。

**本の話は一段落にまとめて書く**のがコツです。段落の単位で切り出されるので、関係ない話が混ざっていると引用が読みにくくなります。

### 表示を変えたいとき

```markdown
[[街とその不確かな壁|あの小説]]
```

縦棒の右が画面に出る文字です。

### 本文で触れずにタグだけつけたいとき

記事の先頭に書きます。この場合は記事の冒頭部分が引用として載ります。

```
books: 銀河鉄道の夜, 街とその不確かな壁
```

### 記事どうしをつなぐ

同じ `[[ ]]` に**記事のタイトル**を書けば、記事どうしもつながります。

```markdown
帰ってから[[図書館のこと]]に書いた窓際の席を思い出した。
```

リンクされた側の記事には「**この記事に触れている記事**」が自動でたまります(バックリンク)。書いた覚えのない線が勝手につながっていくのが、この仕組みのおもしろいところです。

行き先がない `[[ ]]` は薄い点線で表示され、ビルド時に件数が出ます。

## 3. フォルダの中身

```
blog/
├── posts/        ← 記事。基本ここだけ触る
├── books/        ← 本の登録情報
├── pages/        ← about.md
├── static/
│   ├── style.css ← デザイン
│   └── images/   ← 写真・書影
├── build.py      ← ビルド（設定はこの先頭）
├── new.py        ← 記事・本のひな型をつくる
├── publish.sh    ← ビルドして公開
└── docs/         ← 自動生成。編集しない
```

## 4. 記事の設定項目

```
---
title: 夏の終わりに
date: 2026-08-11
tags: 日記, 東京
books: 銀河鉄道の夜
cover: images/sora.jpg
draft: false
---
```

| 項目 | 説明 |
|---|---|
| `title` | タイトル。`[[ ]]` で参照するときの名前にもなる |
| `date` | `YYYY-MM-DD` |
| `tags` | カンマ区切り。トップの絞り込みボタンになる |
| `books` | 本文で触れずに本と紐づけたいとき |
| `cover` | 一覧カードに大きく出す画像 |
| `draft` | `true` で非公開 |

## 5. 本の設定項目

`books/*.md`

```
---
title: 銀河鉄道の夜
author: 宮沢賢治
year: 1934
slug: ginga-tetsudo
aliases: 銀河鉄道, ぎんが
cover: images/books/ginga.jpg
link: https://...
---

この本についての自分のメモ。本のページの上部に出ます。
```

`aliases` を書くと、`[[銀河鉄道]]` のような略称でもリンクされます。
`slug` はURLになるので半角英数で。書影がなければ、書名を組んだ簡素な表紙が自動で作られます。

## 6. 公開する（GitHub Pages・無料）

初回だけ設定が必要です。

```bash
cd ~/Desktop/blog
git init
git add .
git commit -m "つきなみ文庫 開設"
git branch -M main
git remote add origin https://github.com/ユーザー名/blog.git
git push -u origin main
```

GitHubのリポジトリ → **Settings** → **Pages** → Source「Deploy from a branch」、Branch を **`main`** / **`/docs`** にして Save。数分で `https://ユーザー名.github.io/blog/` に出ます。

公開できたら `build.py` 冒頭の `BASE_URL` にそのURLを書いてください（RSS用）。

2回目以降は `./publish.sh` だけです。

Gitを使わないなら [Netlify Drop](https://app.netlify.com/drop) に `docs/` をドラッグでも公開できます。

## 7. 続けるための運用ルール

毎日更新を目標にするなら、以下を強くおすすめします。

**基準を下げる。** 3行でも1記事とする。トップはブロック並びなので、短い記事は小さいタイルになって自然に馴染みます。完成度が日によってばらつくことは、レイアウトの側が引き受けてくれます。

**書く時間を固定する。** 「夜、寝る前の10分」のように時間で決める。ネタができたら書く方式は必ず止まります。

**本の話は一段落にまとめる。** そうしておくと、あとで本のページを開いたときに読めるものが残ります。日々の記事は流れていきますが、本のページには積み上がっていく。この非対称が、このサイトの資産です。

**書けない日は本のメモに逃げる。** `books/` のファイルに一行足すだけでもいい。

**ストックを作らない。** まとめ書きして小出しにすると、書けない日の罪悪感が増えるだけです。

**アクセス数を見ない。** 解析を入れていないのは意図的です。読者数を気にしはじめると、書けるテーマが減ります。

**月に1回、「つながり」ページを眺める。** 図がどう育ったかを見るのが、続けることのごほうびになります。

### 数ヶ月続いたら考えること

- 検索機能（記事100本を超えたあたりから必要）
- 本の読了日・評価の追加（`books/*.md` に項目を足して `build.py` で拾う）
- 独自ドメイン（年1,000円程度。愛着がわいてからで十分）

## 8. 設定を変える

`build.py` の冒頭:

```python
SITE_TITLE = "つきなみ文庫"
SITE_DESCRIPTION = "読んだ本と、日々のこと。"
AUTHOR = "asage"
BASE_URL = ""
```

デザインは `static/style.css` の先頭の変数で:

```css
--ink: #1a1a1a;    /* 文字色 */
--paper: #ffffff;  /* 背景色 */
--measure: 34rem;  /* 記事の1行の長さ */
--wide: 1180px;    /* 一覧の横幅 */
```

一覧の列数は `.grid { column-count: 4 }` です。本文を明朝からゴシックにしたいときは `.post-body` の `var(--serif)` を `var(--sans)` に。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 記事が出てこない | `draft: true` になっていないか、拡張子が `.md` か |
| `[[ ]]` が点線になる | 書名・記事名が正確か、本を `books/` に登録したか確認 |
| 本のページに引用が出ない | 本文の `[[ ]]` か、先頭の `books:` のどちらかが必要 |
| 順番がおかしい | `date:` が `YYYY-MM-DD` か確認 |
| デザインが崩れた | `docs/` を消して `python3 build.py` をやり直す |
| 画像が出ない | 記事内は `../images/...`、`cover:` は `images/...` |
